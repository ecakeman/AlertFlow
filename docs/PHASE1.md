# 阶段 1：SQLite 迁移到 PostgreSQL

日期：2026-10-10

## 连接与迁移

改造前，`db.Open` 打开配置目录里的 SQLite 文件，DSN 带 pragma，`SetMaxOpenConns(1)`，Goose 方言 `sqlite3`。

改造后，进程只读 `ALERTFLOW_DATABASE_URL`，用 `pgx` 的 `database/sql` 驱动连接 PostgreSQL。连接池默认最多 10 个连接、5 个空闲，连接寿命 30 分钟、空闲 5 分钟，可用 `ALERTFLOW_DB_MAX_OPEN`、`ALERTFLOW_DB_MAX_IDLE`、`ALERTFLOW_DB_CONN_MAX_LIFETIME`、`ALERTFLOW_DB_CONN_MAX_IDLE_TIME` 覆盖。启动时 `PingContext` 超时 5 秒，然后跑 Goose `postgres` 方言。

旧的 6 个 SQLite 迁移被一份新的 `00001_init.sql` 替换。它包含 00006 之后的最终结构，不重放 SQLite 的整表重建。空库启动即可。本地没有 `*.db` 或 `config.yaml`，因此没有写 SQLite 导入器，也没有删除用户数据。旧的 `upmonitor.db` 不会在启动时被读取。

切换配置目录只重载 YAML、图片和 Scheduler。用户、检查历史和 Incident 仍在同一个 PostgreSQL。服务定义还在本进程的 `config.yaml`，所以这一版 API 仍然只能单副本：两个进程会共享数据库，但各自持有不同的 YAML。

## 已迁移的约束

- 主键 `BIGINT GENERATED BY DEFAULT AS IDENTITY`
- 时间仍是 Unix 秒 `BIGINT`
- `enabled`、`notify_warnings` 为 `BOOLEAN`
- 集成配置为 `JSONB`
- `checks` 含 `attempts`、`warning` 状态，以及 `(service_id, ts)`、`(service_id, id)`、`(status, ts)` 索引
- `incidents.severity`，部分唯一索引 `idx_incidents_one_ongoing`（`status = 'ongoing'`）
- `notification_log.incident_id` 可空，事件含 `warning`
- 外键级联与原来一致
- 插入用 `RETURNING id`
- 唯一冲突识别 PostgreSQL `23505`
- 归档导入指定 id 之后，把 identity 序列拨到当前最大 id

## 主要文件

- `backend/internal/db/db.go`、`testing.go`、`migrations/00001_init.sql`：驱动、连接池、测试库、最终 schema
- `backend/internal/db/*.go`：占位符、`RETURNING`、布尔和 JSON
- `backend/internal/api/server.go`：用 `ALERTFLOW_DATABASE_URL` 打开数据库；配置目录切换不再换库
- `backend/cmd/alertflow/main.go`：入口从 `cmd/upmonitor` 移过来，环境变量前缀改为 `ALERTFLOW_`
- `backend/go.mod`：模块 `github.com/ecakeman/alertflow`，增加 `pgx`
- `docker-compose.yml`、`.env.example`：PostgreSQL 16 与应用服务
- `.github/workflows/test.yml`：CI 在 PostgreSQL 上跑 `go test ./...`，并构建前端
- `LICENSE` 未改。README 说明基于 upmonitor，且不会导入旧 SQLite

Vue 页面文案没有改。

## 测试

```text
cd backend && ALERTFLOW_TEST_DATABASE_URL='postgres://alertflow:alertflow@127.0.0.1:5432/postgres?sslmode=disable' go test ./...
```

退出码 0。包结果：`api`、`archive`、`config`、`db`、`incident`、`monitor`、`notify` 通过。`cmd/alertflow`、`auth`、`image`、`logger`、`state`、`web` 没有测试文件。测试各自 `CREATE DATABASE alertflow_test_*`，结束后删除。复查 `pg_database` 时没有残留测试库。`TestInsertCheckRollsBack` 覆盖事务回滚。Incident 测试覆盖进行中故障的唯一约束。

```text
cd web-ui && npm run build
```

退出码 0。`vue-tsc --build` 与 `vite build` 完成，约 2.11s。

本地 `docker compose up -d postgres` 使用已有的 `postgres:16-alpine`。空库 Goose 版本 1 已应用。浏览器走通：创建管理员、添加服务、写入一条 online 检查、创建并恢复 Incident、发表评论、打开集成配置页。

```text
docker build -t alertflow:phase1 .
```

失败。Docker Hub `registry-1.docker.io` 连接超时，构建在解析 `docker.io/docker/dockerfile:1` 时停止，没有进入编译。DaoCloud 镜像源的证书也不匹配。这是当前网络阻塞，不是编译错误。镜像没有构建成功。

## 偏离

归档往返测试改为比较 JSON 值，不再比较原始空白和键顺序。`JSONB` 会规范化文本，密钥字段仍然保留。

## 风险与下一阶段

- 没有 SQLite 数据导入。已有 `upmonitor.db` 需要自行备份，不会自动进入 PostgreSQL。
- `config.yaml` 仍在单进程内。多副本 API 还不能共用同一份服务定义。
- Docker 镜像本阶段没有构建通过。
- 通知仍然是检查线程里的 goroutine，没有投递队列。

阶段 2 可以依赖：同一条 PostgreSQL 连接上的事务、`INSERT ... RETURNING`、部分唯一索引，以及按 `service_id` 锁定行。这些已经可用。本阶段没有加 Outbox、Kafka 或 Agent。
